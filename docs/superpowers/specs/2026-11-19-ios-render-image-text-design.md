# 首页刷新、图片准备与文本展示

用户已要求按顺序实现前一轮建议的 1、2、3，并仔细审查。保留现有 Swift 5、iOS 16、数据/权限/保存协议；只使用 Local 或合成数据，Production 只构建，不提交或覆盖既有工作。

1. 首页卡片只依赖自己的展示输入。移除 NotesCard 对整个 HomeCardsManager 的多余订阅及参数；保留卡片数据更新、菜单、导航、引导与 scoped preview 的独立刷新。通过真实 SwiftUI 宿主和 DEBUG 诊断记录 body 次数，证明无关 loading/其他卡片状态不再直接触发每行计算。
2. 为已有本地笔记图片预览增加共用准备入口。现有 UIImage 异步缩略图能力继续使用或以等价 ImageIO 准备实现；成品按账号/环境、笔记、媒体内容版本和目标像素尺寸隔离。合并相同在途工作，并按解码后的字节数限制缓存，处理内存警告。缓存不能绕过当前 scope、正文引用和附件身份校验；删除、变更、退出账号后的迟到结果不得展示。一个消费者取消不影响另一个，实际并发准备有界。图片引用抽取移出 MainActor，按精确正文版本复用，保持文件完整性校验。该步骤覆盖已确认重复工作的 LocalNoteThumbnail 及其 NoteLibraryStore 媒体链路；远程 AsyncImage 不改网络授权合同。
3. HTMLTextRenderer 不再在 body 内执行 HTML 替换和正则。保持原转换顺序、空白/实体/截行及样式行为；在已有有界预览执行机制上准备不可变纯文本，内容改变时使旧结果失效，并复用同一内容版本。聊天、个人主页、回收站、关联笔记等现有调用者均接入。匿名展示/合成 fixture 不能因优化变成空白；纯文本转换不能扩大数据读取权限。

不创建全局任务框架或修改同步持久化。验证以实际转换/读取次数、线程、真实并发、内存预算、SwiftUI 计算次数和固定样本耗时为依据；不能据此宣称真机帧率提升。

完成标准：三步均有运行时行为与回归证据；CoreFlow、编辑器和 App 相关测试通过；相关模拟器流程及 Local/Production 构建；当前执行文档、历史与 QA 记录同步；一次独立审查及必要修复。
