# 本轮 iOS 反馈修正

入口：`http://127.0.0.1:8768/2026-10-26-review-fixes/`。

这里展示真实 App 的 Home 与编辑器：7 个状态、浅深色共14张原生截图。额外保存了收起键盘后的状态截图；所有图片可点击看原尺寸。

- Home 正文与标签之间的空隙回到13pt布局间距，44pt菜单点击区不再撑高这段空白。
- 排序改为系统菜单，沿用既有四种排序项；Collections 不伪装支持后端没有的排序。
- 新建和已有短笔记都将剩余空间分配给真实编辑器；这个高度会进入实际可编辑正文，页面下部空白也能点击落笔。长内容继续自然增长，输入后保持整页书写高度。
- 编辑页覆盖 Home 的期间持续隐藏 Tab Bar，关闭后恢复；键盘变化不会把底栏错误带回来。
- 标签右侧恢复工具按钮，连接既有 Add tag / Format text；进入格式工具会将焦点交还正文，标签输入保留 Return 提交与空白校验。点击普通标签先显示明确删除菜单，只读兼容状态禁用写作工具。

Explore 的固定大卡片、滑动反馈、历史入口和整页阅读是另一个独立原生提案：[V9](../2026-10-21-native-visual-reform/revisions/v9-fixed-deck-reader/gallery/)。本轮没有将这个提案替换进真实 App 的 Explore / Reader。

截图来自 Xcode27.1、iPhone17Pro/iOS26.5。使用 `--dev-preview` 离线样本。没有测试真实登录、联网收藏、AI生成或服务器保存；没有修改后端合同或依赖版本，未启动 Production App。先前版本和原 fidelity 审阅页均保留。

Local 的 App / UI test build 和 Production 的 Simulator build 均通过；CoreFlow 本次114项测试、BlockNoteEditor 57项测试通过。实际界面回归按单项记录，初次失败及后续修正结果一并保留，见 [VALIDATION.md](VALIDATION.md)，不能把含失败的整批日志当成全通过。

最终浅色整页写作测试通过；最终深色的只读保护、Home进入编辑器、整页写作、排序4项均通过。已有短笔记、键盘与菜单、格式工具、标签Return提交及非法输入等选定回归也有独立通过证据；这些是本轮相关路径验证，不是完整项目所有UI测试。

真实正文的高度测试确认：编辑器初始化会先从 revision 0 稳定到 2；先建立这个稳定基线，再改变显示高度。高度从520pt缩到280pt再取消下限，正文JSON、Markdown和revision都未改变。这是外观变化不改文档的验证，不是“初始化从未发生事件”的声明。
